# Workflow updates: antislop review

Date: October 9, 2026, Asia/Manila. Mode: after, selected for this session.

This review covers the changed stall, announcement, assignment, notification, and payment controls. It does not re-audit the rest of the application or replace the earlier audit.

## Direction and reasons

Reading these as property administration forms for staff and tenants, using the application's existing visual language. ENERGY 1 / RHYTHM 1 / MOTION 1.

- Keep the existing fonts, palette, and form components so the added controls belong to the current app.
- Place Pending payment in the existing filter because it describes an assignment awaiting its initial payment.
- Show the pending tenant in the table and detail so staff can identify who holds the reservation.
- Put SMS alongside email because both are optional announcement delivery channels.
- Keep recipient counts beside SMS so staff can see the audience and missing phone numbers before posting.
- Put Duration before the dates because the preset determines the end date. Stack date fields on phones so each input has room.
- Keep gateway-confirmed payment status authoritative, and refresh the displayed values while online payments are pending.

## Findings

No additional findings were identified in the changed controls during this focused review. Existing styles and unrelated workspace changes were retained.

## Delivery gate

- Hard Gate PASS for changed controls: no fabricated content or assets; SMS has an accessible checkbox label and help text; assignment controls have explicit labels. At 390 px the announcement page's scroll width was 381 px, and assignment date fields occupied one grid column. The new SMS help text measured 7.92:1 contrast against its dark form background. Empty, disabled, failure, and unauthorized states are covered by the workflow tests.
- Purpose Gate PASS: controls follow the established app components; placement and grouping reasons are recorded above. No decorative assets, gradients, fonts, or animation systems were introduced.
- Liveliness PASS for these form additions: the existing primary form action remains the focal point, grouped fields retain structural spacing, and existing accents communicate actions and payment state. Dials are ENERGY 1 / RHYTHM 1 / MOTION 1.
- Craftsmanship PASS for the requested workflows: 86 affected tests and 298 assertions passed; the Vite build passed. Browser checks confirmed pending filtering and tenant detail, preset recalculation, Custom switching, keyboard SMS toggling, audience counts, removal of Mark as Paid, and reopening a legacy ticket notification from the same ticket page. No browser console errors were observed during these checks.

## Validation limits

Payment signatures, settlement, duplicate callbacks, lease activation, selection cleanup, modal refresh, cancellation, and owner isolation were verified with automated tests. SQLite tests verify repeated fulfillment, while production concurrency protection was checked in the transaction and row-lock implementation; a concurrent MySQL load test was not run.

SMS dispatch, truncation, missing phones, disabled SMS, deduplication, audience targeting, and provider failures were tested without sending real messages. No live PayMongo transaction or production Semaphore request was performed. Browser checks used local data and did not create assignments, post announcements, record payments, or send ticket messages.
