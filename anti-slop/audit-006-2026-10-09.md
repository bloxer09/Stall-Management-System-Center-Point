# Announcements table and creation dialog

Scope: the user's requested conversion of the admin announcements page to the existing admin table and dialog patterns. Session mode: after. The user's request authorizes these changes.

Design direction: retain Center Point's current admin typography, primary action color, rounded table container, and modal styling. ENERGY 1 / RHYTHM 1 / MOTION 1. The table makes audience, delivery, and posting information comparable; the dialog separates composition from reviewing posted notices. No visual assets or invented production content were added.

1. Resolved: the creation form competed with posted announcements, which appeared as a list instead of the requested table (C-3, R-31). Creation now opens through New announcement; a full-width table shows announcement text, audience, delivery, posting information, and deletion actions.
2. Resolved during verification: disabling the opener before the dialog appeared prevented focus from returning to it (R-32). The opener remains focusable. The dialog traps focus, supports Escape, Close, and Cancel, and restores focus to the opener. Closing preserves the draft; posting resets it and closes the dialog.

Verification: nine targeted Chromium tests passed, with no retries, skips, or flaky results. Existing announcement journeys, maximum-length and required-field validation, rapid clicks, and refresh-after-commit scenarios passed. New coverage verifies table headers and empty state, floor and email selections, draft persistence, reset after posting, deletion, and mobile HTTP 500 recovery with exactly one stored announcement. All writes used the isolated SQLite database and runtime storage.

Delivery review: inspected the desktop table and 375px dark dialog screenshots. Table scrolling stays within its labeled, keyboard-focusable region; the page has no horizontal overflow. The mobile dialog scrolls to its controls and retains the application's shared focus management and viewport sizing. Controls have at least 44px height. Validation errors are associated with their fields and announced; request errors use the shared persistent alert. Content uses existing theme colors and text labels for delivery information. PHP syntax, Blade compilation, TypeScript checks, asset build, and changed-file whitespace checks passed.

Artifacts: Playwright HTML report, JSON and JUnit results, and explicit announcements-table and announcements-mobile-error screenshot attachments. The complete application suite was not rerun for this change; the earlier 51-test run remains a separate verification result. Browser device emulation, Firefox, WebKit, and production concurrency were not part of this targeted run.
