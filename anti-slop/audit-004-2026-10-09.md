# Registered stall application review

October 9, 2026. Antislop mode: after, session override. Focus: application access, account identity, and authentication return navigation.

## Direction and changes

Reading this as a public stall directory and tenant application form in the current app's visual language. ENERGY 1 / RHYTHM 1 / MOTION 1. The primary guest action is signing in; registration is the secondary outlined action. Existing modal, typography, accent, spacing, and responsive behavior are retained. No assets or decorative motion were added.

Guests can browse stalls and join availability waitlists. Applying requires an active tenant account. Name and email are read-only and enforced again on the server; phone remains editable. Approval uses the linked account, with legacy guest approval preserved. Password login, registration, and both social callbacks consume a session-held stall ID and construct the return URL internally.

## Delivery gate

- Hard Gate PASS for changed controls: both guest links opened the appropriate authentication dialog; tenant login returned to F-01; the tenant application form showed prefilled identity and editable phone. At 390 × 844 the document scroll width was 381 px, and modal client/scroll widths were both 341 px. Tab reached the next control with a solid outline; Escape dismissed dialogs. New full-opacity copy uses the same computed colors previously measured at 6.49:1 on the dark modal and 14.68:1 on white. Light and dark views were inspected; browser console errors were empty. No fabricated claims or assets were introduced.
- Purpose Gate PASS: the filled sign-in link and outlined registration link distinguish returning users from new applicants. Read-only identity makes the account relationship visible. Reasons for retained components and spacing are recorded above; no decorative techniques were added.
- Liveliness PASS: ENERGY 1 / RHYTHM 1 / MOTION 1 matches the existing directory. The sign-in action is the focal point, grouped links provide structure, and the existing primary accent and modal identity remain consistent.
- Craftsmanship PASS: the affected application/authentication suites passed 45 tests with 235 assertions. After updating the old guest CAPTCHA fixture, the registration-access and CAPTCHA suites passed 14 tests with 80 assertions. The Vite production build passed. Tests cover guest and role rejection, account deactivation after opening, ownership tampering, linked-account approval, legacy approval, uploads, duplicate submissions, availability changes, notification behavior, registration/login return navigation, both social callbacks, and invalid return targets.

## Evidence and limits

Final full PHPUnit run: 393 tests passed with 1,663 assertions. Scoped diff whitespace checks and PHP syntax checks passed.

Browser checks used a temporary local tenant account, which was removed afterwards. No application was submitted in the real database, and no outbound application notification was sent. CAPTCHA and social-provider responses were faked in PHPUnit; no live provider login or CAPTCHA was performed. Browser theme and viewport were restored and the temporary tab closed.
