# Save Profile review

Mode: after (session override).

Scope: profile submission, phone validation, and success feedback. Existing profile layout and styles provide the design direction; this fix adds no visual design or assets.

## Findings

No remaining antislop findings within this change.

## Verification

The two phone failure cases first reproduced database uniqueness exceptions. The handler now trims phone input, validates uniqueness while excluding the current account, and stores an empty optional phone as null.

A successful save previously left the native modal dialog open, obscuring the global success notification. The handler now closes the dialog after saving. Validation failures leave it open.

The isolated browser check exercised Save Profile with another test account's phone, confirmed the inline error, then cleared the phone and confirmed the dialog closed and the success notification became visible. Reopening the profile showed the saved empty phone. No browser console errors were recorded. Test data was confined to the E2E SQLite database.

Profile and two-factor tests: 16 passed, 66 assertions. Avatar saving and retaining the account's existing phone also passed. PHP syntax check passed.
